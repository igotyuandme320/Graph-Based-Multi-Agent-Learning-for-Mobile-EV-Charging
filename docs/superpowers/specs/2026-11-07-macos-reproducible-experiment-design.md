# macOS 可复现实验设计

## 意图

把现有的电动汽车（IEV）与移动充电站（MCS）多智能体 DQN 实验从一份依赖 Windows 本地路径、隐式工作目录和旧版 Python API 的研究代码，整理为可在 macOS 上安装、配置、训练、评估和复现的小型项目。

## 目标

- 不改变现有仿真和 DQN 的研究逻辑及随附数据、预训练模型。
- 将数据、模型和结果目录解析为相对项目根目录的跨平台路径。
- 提供明确的 Python 依赖、命令行入口和使用说明。
- 支持可快速完成的 smoke 测试和保留原始规模的实验配置。
- 修复 Python 3.8+ / PyTorch CPU 或 Apple Silicon 环境下阻止启动的兼容性问题。

## 非目标

- 不重新设计奖励函数、训练算法或研究结论。
- 不重新训练或替换已附带的模型。
- 不提供 GPU/CUDA 专属安装方案；macOS 默认使用 PyTorch CPU/MPS 自动可用的设备策略。

## 方案比较

1. **仅修复硬编码路径。** 改动最小，但仍需要用户记住脚本目录、模型名称和依赖版本，实验不可复现。
2. **整理为可配置的实验 CLI（采用）。** 保留已有 Python 模块，集中管理路径与配置，提供 `evaluate`、`train` 和小规模验证命令；可在不改变算法的情况下稳定运行并产出结果。
3. **重写为 Gymnasium/现代 RL 框架。** 架构最现代，但会改变实验接口和结果可比性，超出本次范围。

选择方案 2，因为它直接解决 macOS 可运行性，同时最大限度保留原实验。

## 实施设计

- 引入项目路径与默认配置模块：用 `pathlib` 定位 `data/`、`DQN/exp/models2/`、输出目录，禁止依赖当前工作目录和 Windows 盘符。
- 给 DQN 训练循环提供显式运行参数（训练轮数、每轮步数、随机种子、评估/训练、模型路径、输出目录），并用 `time.perf_counter()` 取代已删除的 `time.clock()`。
- 新建轻量命令行启动器：
  - `python -m ... evaluate --smoke`：以极小车辆/MCS 数运行已提供的策略，确认环境、模型加载和结果写入；
  - `python -m ... train ...`：保留训练入口；
  - 支持现有预训练模型的选择。
- 添加 `requirements.txt`、README（中文）和 `.gitignore`，并对核心路径、模型加载与短回合仿真编写测试。
- 在本机创建虚拟环境并实际执行测试和 smoke 评估，记录可复制的启动命令。

## 验收标准

- 从项目根目录按 README 的命令创建环境、安装依赖并运行 smoke 评估，无 Windows 路径或已移除 API 错误。
- smoke 评估生成结构化指标文件，且默认不覆盖已有模型/历史数据。
- 测试覆盖路径解析、模型载入及一个短环境回合。
